# 共有理解を育てる伴走役の試行版

2026-10-13。ブランチ：`codex/purpose-partner-shared-understanding`。雛形v0.2への指針追加で、正式版への統合前に新しい仕事場で試す版です。

## なぜ試すのか

人間とAIは、すれ違いを修正し、具体例を見せ合い、合意した経験から、互いの言葉を受け取る前提を育てます。その経験が記録に残り、後の仕事で使われれば、共有できたことを足場に次の問いへ進めるのではないか、という仮説を試します。

動機の伴走役に、何を大切にしたいかとともに、理解を共有できた手掛かりを育てる指針を追加しました。毎回の記録・質問・分析は義務にせず、本人が気づき、試し、考えを深める時間も大切にします。短い対話での合意も、長い対話での構想の発展も材料です。

## この版から新しい仕事場を作る

AIへ次のように頼めます。保存先は新しい事業所に合わせて決めます。

> https://github.com/kentaroid-bot/Dokodemo-Desk のブランチ `codex/purpose-partner-shared-understanding` を取得してREADMEを読み、総えもんとして案内してください。別の新しいフォルダへ空の仕事場を生成し、この版の指針を含む動機の伴走役を初回案内で作成・登録してください。取得したコミットと試行開始日は、導入作業の記録へ残してください。

コマンドで取得・生成する場合の例です。Python 3.9以降を使います。既存フォルダには上書きしません。

```sh
git clone --branch codex/purpose-partner-shared-understanding --single-branch https://github.com/kentaroid-bot/Dokodemo-Desk.git Dokodemo-Desk-trial
cd Dokodemo-Desk-trial
git rev-parse HEAD
python3 -B create_workspace.py ../my-workspace-trial --name "私たちの仕事場" --blank
```

生成後は、その仕事場の `START.md` をAIに読んでもらいます。生成直後は総えもん・UI担当の2役で、改善した伴走役の**ひな形**が入っています。伴走役そのものは本人との対話を受けて作成し、名簿へ登録します。生成だけで本人の動機を理解した担当が完成するわけではありません。

取得したコミット・開始日・採用した変更を、既存の導入TASKへ記録します。コードの取得元を明らかにするための記録で、追加の面談や質問票は不要です。ブランチが後で更新されても、取得済みの仕事場はそのまま使えます。既存の仕事場は自動更新せず、必要な差分だけ取り込みます。

## 指針と記録先

指針の原本は[伴走役のひな形](../template/workspace/agents/templates/purpose-partner.md#協働で育った理解を次に生かす)。[初回案内](../template/workspace/agents/workflows/onboarding.md)で本人用の役割へ引き継ぎ、架空の練習版も同じ指針を参照します。

動機や判断軸の変化は生成先の `workspace/purpose.md` へ、仕事固有の言い直しや具体例は既存の作業票・成果物のそばへ、次に役立つ分だけ残します。必要に応じてリンクで結び、会話全文や同じ進捗を複製しません。

## 普通に仕事をしながら確かめる

振り返りや引き継ぎの際、材料があるときだけ、次のような例を既存の記録へ短く残します。

- 前の訂正や採用例が、後の依頼を受け取る手掛かりになった。
- 共有できた前提を使って、同じ説明に戻らず新しい問いへ進めた。
- 長い対話の中で本人の気づきや構想が深まった。
- 記録があっても使われなかった、古い理解を当てはめた、記録する手間が仕事の負担になった。

本人のOKは、その提案や解釈についての合意として扱います。短い往復や肯定の数だけを成功指標にせず、何が共有され、後にどう生きたかを見ます。本人の言葉とAIの解釈を分け、成長度の採点や性格の固定分類はしません。

この版は文書による立ち回りの指針です。自動巡回・別チャットへの送信・学習処理は追加しません。実利用での有効性は未確認で、技術的な生成・参照の確認とは分けて評価します。
