# プラグイン導入経路の構想

2026-10-10。将来の設計案。プラグイン本体と接続は未実装で、現在の利用にプラグインは必要ない。[README](../README.md)からGitHub経由で本体を取得して始める。

## 目的

見つけやすさと導入案内を補い、利用者が自分の仕事場を持ち運び、育てる体験につなげる。仕事場は利用者の保存先に置き、配布元やプラグインのキャッシュから独立させる。

## 想定する入口

| 入口 | 目的 |
|---|---|
| setup | 初めての仕事場を用意し、総えもんの案内とUIまでつなぐ |
| add-desk | 必要な担当と名簿・原本を整える |
| resume | 中断した導入や別端末への復元を続ける |
| maintain | 全体を確認し、依頼された範囲の不整合や担当構成を整える |

日常業務は必要な担当へ直接頼める。毎回setupやresumeを通す手続きにはしない。動機の伴走役を全作業の承認者にも置かない。

## 本体との関係

原本はこのリポジトリの生成器・雛形・手順。パッケージ用の雛形を別々に手編集せず、配布時に対応する版を明示する。現行生成器は練習版から空の版へ変換するため、生成済みの空の雛形へそのまま差し替えて同じ処理を実行しない。

更新・取り外し・再導入でも利用者の目的・役割・成果を保持する。仕事場全体を自動で置換・削除しない。複数の仕事場の目的や接続先を自動で共用しない。

## 実装時に決めること

対象アプリのその時点の公式仕様を確認し、パッケージ形式、導入入口、利用できるファイル操作・実行機能、配布方法を選ぶ。最初はsetupとresumeを小さく試し、その後で担当追加・整備へ進める。

導入途中の再開、同じ依頼の再実行、既存フォルダ、利用者が編集した原本、複数の仕事場、アンインストール後の継続を確認する。通知・別チャット起動・常駐処理・外部連携は個別の後続設計とし、プラグインの存在だけで接続済みとはしない。

完成の中心は、利用者が一つの仕事を始め、担当と成果を見つけ、次の会話で再開できること。本体の[初回試験](first-run-test.md)を先に進める。
