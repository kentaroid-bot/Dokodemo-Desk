# どこでもデスクの導入設計

2026-10-10。初期公開版が採用する設計。実際にAIが読む手順は[初回案内](../template/workspace/agents/workflows/onboarding.md)、確認済みの範囲は[検証記録](../VALIDATION.md)を参照する。

## 目指す体験

**総えもんに出会う → 自分の仕事場と相棒ができる → UIで仕事の進み方が見える → 次の担当へ頼める。**

目的・役割・成果・続き方を利用者が所有するファイルに残し、会話や端末が変わっても仕事を続けられることを目指す。仕事場づくりそのものを最初の協働体験にする。

総えもん（そうえもん）は使い方案内・担当作成・全体統括を受け持つ。呼び名は利用者が変更できる。UI担当と総えもんは雛形にあり、最初の対話で利用者専用の動機の伴走役を加える。必要な業務担当は仕事に応じて増やす。

## 対象と保存先

PC上で、フォルダの読み書き、Python実行、ローカルUI表示、原本の継続保存ができるAI環境を対象にする。macOSのCodexで初回試用を行った。ほかのAI環境・OSは個別に検証する。

配布元と、利用者が育てる仕事場を別フォルダに置く。仕事場の表示名を自由に決められ、配布元の名前まで変える必要はない。クラウドだけ・スマートフォンだけでの新規導入や、準備済み仕事場の遠隔利用は今後の検証対象。

## 一巡の流れ

| 段階 | 案内すること | 残すもの |
|---|---|---|
| 取得 | 公開リポジトリを取得し、READMEから総えもんの役割と手順を読む | 取得した版と場所 |
| 説明 | 必要な担当を増やし、仕事と成果を記録・画面で見られることを紹介 | 利用者が始めたいこと |
| 保存先 | 新しい仕事場か、既存の仕事場からの再開かを確認 | 保存先と実行環境 |
| 動機 | 既知の発言を使い、不足だけを聞く | 本人の言葉・AIの理解・暫定部分を分けた目的原本 |
| 相棒 | 動機の伴走役を作り、名簿へ登録する | 役割と目的への参照 |
| UI | 導入TASKと担当・成果を画面で確かめる | 導入作業の原本 |
| 続き | 成果・担当・次の頼み方を紹介する | 次の一手と続ける場所 |

質問を固定順に全部行うチェックリストにはしない。口調・名前・保存方式は必要に応じて決め、既知の情報を聞き直さない。GitHubの利用や認証済みという事実だけで習熟度を推定しない。

## 記録と役割

導入の状態・成果・次の一手はTASKへ一度だけ記録する。workspace/onboarding.mdには設定結果とその原本への入口を置く。UI完成前はチャットで進捗を短く示し、保存先が決まったら実施結果をTASKへ移す。画面表示と本人の確認は分けて記録する。

共通の係はrolesの役割文書、作家・研究・開発などの専門担当は担当定義を含むdesksの文書にまとめる。担当の入口は名簿に一本化する。複数の机でプロフィールを共用したくなったときに分離できる。担当IDと原本を保ち、同じ仕事の進捗を複製しない。

役割を作ったこと、同じAIが兼務すること、別チャットを起動することを区別して紹介する。継続業務には専用チャットを提案し、同じチャットで続ける希望も尊重する。専用チャットを選んだら目的・訂正・成果・未完了事項・次の一手を原本と開始文で引き継ぐ。チャットの作成・送信は本人の依頼範囲で行う。

## 保存と次の検証

ローカル、ZIP、本人の非公開GitHubから選べ、後で決めることもできる。認証、実チャット、定期起動、秘密や対象外素材はGitだけでは移らない。生成器は既存フォルダへの上書きを拒否する。雛形の更新は本人の編集を保って必要な箇所だけ取り込む。

次は[取得からの試験](first-run-test.md)で、初対面の利用者への案内、担当の紹介、専用チャットからの再開と、環境ごとの動作を確かめる。[プラグイン](plugin-design.md)は任意の将来案。
