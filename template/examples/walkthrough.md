# 架空の一件で試す

「小さな制作室」は架空の練習です。空の版には例の担当や仕事を入れません。練習には例入りの新しいコピーを使います。

## 1. 目的から担当へ

画面の「この仕事場の目的」を開きます。「事務の負担を減らして、制作と顧客との対話に時間を戻したい」という架空の動機を確認します。続いて「制作室の伴走役」を選び、目的を日々の仕事につなぐ役割を読みます。

総えもんは使い方の案内・仲間づくり・全体統括、伴走役は動機と次の仕事、UI担当は仕事の地図を受け持ちます。これらの役割は同じ会話で兼務しても構いません。

## 2. 仕事の所在をつかむ

「担当とつながり」で見積支援デスクを選びます。役割を読み、関連する仕事へ進み、作業票から見積下書きを開きます。「誰が・何を作り・誰の確認待ちか」を確かめます。

## 3. 原本を変え、表示を確かめる

手元のAIか自分で、練習用TASK.mdの状態を「確認済み・練習完了」、次の一手を「今回の練習は完了。外部への送信はしない」にし、更新日時を実際の時刻にします。「記録を更新」を押して表示の一致を確かめます。

## 4. 一つ増やす

総えもんへ「請求書の下書きを作る練習用デスクを追加したい」と頼みます。[担当追加](../workspace/agents/workflows/add-desk.md)に沿って、目的との関係、役割・名簿・保存先・一件の作業票をそろえ、表示を確認します。請求・送信の実行は含めません。

## 5. 続きを頼む・別の場所へ移る

[引き継ぎ手順](../workspace/agents/workflows/handoff.md)で、次の会話へ目的・役割・作業票を渡します。説明を最初から繰り返さず、次の一手を読み取れるか確認します。会話を分けなければ原本の読み合わせでも試せます。

[ZIP保存](../workspace/recovery/README.md)から新しい場所へ復元し、目的・担当・成果・次の一手を確認します。[GitHub保存](../workspace/recovery/github.md)を採用した場合は、送信した版を新しくクローンして同じ確認を行います。練習だけを理由に外部リポジトリを作りません。

## 6. 自分たちの仕事場へ

空の版で総えもんの初回案内を試します。動機を短く伝え、本人専用の伴走役が役割と名簿に登録され、目的原本につながるところを確認します。仕事場づくりのTASKへ実際の成果と続きを残し、導入記録には設定とそのTASKへのリンクを置きます。次の会話で同じ担当を重複作成しないことを確かめます。架空の設定を本人の目的として引き継ぎません。

途中で自分で理解したいときは、その余地を残してもらえます。急ぐときは整理を任せられます。試行で分かったことを記録し、必要な役割を変えたり、休止・再開したりして育てます。
