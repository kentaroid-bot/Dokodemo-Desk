# 共通の係・専門デスクを増やす・変える

総えもんへ、手伝ってほしい仕事を伝えます。[仕事場の目的](../../purpose.md)との関係、目的・入力・成果物・人間が確認すること・今回の終了点を整理し、既存担当で足りるか確かめます。初回は[導入案内](onboarding.md)に従い、動機の伴走役を最初の利用者専用担当として具体化します。

## 新しい担当を作る — 総えもん

[共通の係と専門デスク](../roles-and-desks.md)の基本形に沿って、担当する範囲から置き場所を選びます。

1. **仕事場全体を支える係**：総務・UI・保存・メール・案内などは[ロールひな形](../templates/role.md)をworkspace/agents/roles/<担当ID>.mdへ置き、役割・判断方針・フロー・記録の場所を記します。専用デスクを一緒に作ることは必須にしません。
2. **固有のテーマや案件を持つ専門担当**：作家・研究・開発などは[デスクひな形](../templates/desk.md)をworkspace/agents/desks/<デスクID>.mdへ置き、担当の役割と仕事の案内を一つにまとめます。最初は別のロール文書を作らず、その担当を机の主担当にします。
3. [名簿](../registry.md)へ担当を一行登録し、実際に担当定義を置いた文書へ原本リンクを向けます。担当IDは英小文字・数字・ハイフンで重複しない値にします。専門デスクのIDは、最初は担当IDと同じで構いません。
4. 成果物の場所をprojects/<案件名>/に用意し、必要な案件をworkspace/catalog.jsonへ登録します。既存成果を使うならその場所を維持します。業務を始めるときに[仕事の記録](work-record.md)を作り、担当ID・役割やデスクの原本・成果物を結びます。担当設置だけで架空の実績を作りません。
5. 画面の「記録を更新」で担当と実際に作った仕事が見え、原本へたどれることを確認します。新しい担当の名前・任せられる範囲・続きの頼み方を一度紹介します。同じチャットで引き受けるなら、総えもんがその役を兼務して進めると伝えます。
6. 継続する専門業務には、後から相談や成果を探しやすくするため、専用チャットを勧めます。同じチャットでの継続も選べます。[引き継ぎ手順](handoff.md)に沿って、選んだ方法で再開できる原本と開始文を整えます。担当設置だけで新しいチャットを起動・送信しません。

役割を作る理由は、その場の返答に名前を付けるためではなく、継続して任せる責任・判断方針・原本・相談先を残すためです。AI自身がすぐ仕事を進められる場合も、利用者が「誰ができて、次からどこへ頼めるか」を理解できるところまで案内します。毎回の名乗り直しやキャラクター演技は必要ありません。

既に進めている仕事を新しい担当へ移す場合は、同じ作業票の担当・次の一手・更新日時を更新し、重要な訂正と途中の成果を保ちます。担当を作ったためだけに同じ仕事の進捗原本を増やしません。

動機の伴走役には[専用ひな形](../templates/purpose-partner.md)を使い、目的原本と関連作業を参照します。UIのように成果物を作る共通係もあります。分類は成果物の有無で固定せず、担当する範囲で決めます。

## 同じ担当の机を増やす — その担当

別作品・別案件を頼まれたら、今の机に作業票やフォルダを追加すれば足りるか、独立した机があると扱いやすいかを判断します。資料・設定・長期の進み具合を別にたどりたいときは、机を分ける目安になります。

1. 分ける理由を短く伝え、任された仕事の範囲で新しいデスクを整えます。主担当には既存の担当IDを記します。
2. 担当定義は既存のデスクから参照できます。複数の机で共用しやすくしたい場合は、その部分を[ロールひな形](../templates/role.md)を参考に独立させ、元のデスクには参照を残します。定義を二重管理せず、担当IDを維持します。
3. 名簿の原本から受け持つ机へたどれるようにし、元の机からの案内、成果物の場所、必要な台帳項目・作業票を更新します。定義を独立させた場合は名簿の原本リンクも更新します。机だけの追加では担当行を増やしません。
4. 新しい仕事が同じ担当に結び付くことと、画面で原本・成果へたどれることを確認し、利用者へ場所と次の一手を伝えます。

机の追加ごとに総えもんの承認を待つ必要はありません。新しい担当の作成、担当間の責任調整、共通ルールの変更は総えもんへ相談します。専用チャット・自動起動・外部接続は、本人の依頼範囲と実環境を別に確認します。

## 主担当と共同作業

机の主担当は最初に設定した担当を基本とし、利用者の依頼で変更できます。変更時はデスク原本と案内を更新し、未完了の仕事の受け渡しを記します。各作業票にはその仕事を持つ担当を一人記し、必要なら関係する担当を併記します。個別作業だけの担当変更で、机の主担当を自動的に変えません。

複数の担当が同じ机を使う場合は、主担当と協力する担当のID・分担を記します。通知の受領・共有板への各担当の回答と、実作業の引き受けを区別し、同じ仕事や進捗を重複して作りません。この文書は運用上の約束であり、同時書き込みを防ぐロック機構は未実装です。

## 変更・休止・再開

担当範囲を変えるときは、名簿が指す担当定義の原本を直し、理由と影響する仕事を記録します。既存の文書構成を一括移行する必要はありません。利用者の希望でプロフィールと机を分けた構成も使えます。

担当を休止するときは名簿を「休止中」にし、未完了の仕事の次の担当・行動を更新します。一つの机だけを休止する場合はその机に記し、ほかの机で働く担当まで休止にしません。原本や過去の記録は残します。実際の自動実行がある環境では、その停止・再開も別に確認します。

[仕事の渡し方](handoff.md)に従い、使うAIに担当定義・関係する手順・机と作業票を読んでもらいます。文書の設置だけでAIが起動するわけではありません。
