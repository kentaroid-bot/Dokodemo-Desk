# 仕事の記録を画面へつなぐ

1. 複数工程の仕事を始めるとき、[TASKひな形](../templates/TASK.md)をoperations/jobs/<作業ID>/TASK.mdへコピーします。同じ仕事にREADMEとTASK両方の現在地を作りません。
2. 作業ID・担当・目的・状態・更新日時・今回の到達点・次の一手・報告先を実際の内容で埋めます。担当は名簿のIDを使います。
3. 担当が、開始・状態変化・中断・終了時に同じ原本を更新します。詳細な根拠や成果物へのリンクは本文に残します。
4. 画面を開くか「記録を更新」で原本を読み直し、担当・状態・次の一手が一致することを確かめます。書かれていない進捗は推測しません。

依頼を受けるときと振り返るとき、[仕事場の目的](../../purpose.md)との関係を確認します。目的が未定なら今回分かっている動機から進めます。GitHub保存を採用している場合は[保存と再開](../../recovery/github.md)に従い、終了時に成果と次の一手を送信済みの版へそろえます。失敗・未送信は同じ作業票の引き継ぎに残します。

読み取りの目印は `<!-- monku-work:v1 -->` と `<!-- /monku-work -->`。その間にはひな形と同じ日本語の項目を一行ずつ書きます。日時は時差を含めます。状態は自由な日本語で、実際に確かめた内容にします。

本人から「これ、動機の伴走役に記録して」と頼まれたら、担当は[伴走役の続き方](../templates/purpose-partner.md#続き方)に沿って同じ会話で兼務し、purpose.mdへ気づきを残します。AIから仕事と動機のつながりを示すこともできます。本人の言葉とAIの解釈を分け、現在の目的と理解の歩みへ反映します。小さな気づきだけのために新しい作業票を作らず、必要な根拠は今の作業票から参照します。

日報はoperations/reports/daily、月報はmonthlyに保存します。日報は作業票の要約で、別の進捗原本にはしません。自動の日報作成は設定していません。
