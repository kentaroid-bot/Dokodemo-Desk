# GitHubで保存し、別の端末で続ける

手元のフォルダを仕事机、GitHubを履歴付きの保管庫として使います。別のパソコンへ最新の仕事場を取り出し、総えもんに続きから案内してもらえます。Git操作は総えもんに頼めます。

## 初めて設定する

> この仕事場を、私の非公開GitHubリポジトリへ保存できるようにしたいです。保存する範囲と送り先を一緒に整理し、再開方法まで案内してください。

配布用のdokodemo-deskと、自分たちの仕事用リポジトリを分けます。仕事用は利用者自身のアカウントまたは組織の所有で作ります。既存の保存先があれば再利用できます。まず[ZIP保存](README.md)だけで始め、GitHub接続は後からでも構いません。

総えもんは、所有者・名前・非公開設定・送信する範囲とGitHubへの実際のアクセスを確認し、本人の依頼の範囲で作成・設定します。Codex等のAIアプリのログインと、GitHubへのアクセスは別の準備です。

## 何を引き継ぐか

| 保存するもの | 別に用意するもの |
|---|---|
| 共通姿勢・ルール・目的・導入記録 | AIアプリやGitHubへのログイン |
| 名簿・役割・手順・共有できるスキル | 秘密の値、APIキー、環境ごとの接続先 |
| 作業票・判断・成果・次の一手 | 実チャットID、常駐プロセス、定期起動 |
| 読み取りUIと再開に必要な説明 | 保存対象外の素材や必要な実行ツール |

パスワードや秘密はリポジトリへ入れません。.gitignoreは除外の入口で、既に追跡されたファイルや別の名前の秘密まで自動で取り除くものではありません。送信対象の差分を確認して保存します。大きな素材・顧客資料・外部保存物は、共有範囲と所在・復元方法を決めます。GitHubだけで全データを保存できたと扱いません。

## 日々の開始と終了

1. **開始時**：送り先と作業ブランチ、手元の未保存変更を確認して、GitHubの新しい変更を取得します。衝突があれば双方を残し、内容を見て解決します。強制上書きで合わせません。
2. **終了時**：仕事の担当が作業票の成果・残る仕事・次の一手を更新します。送信対象を確認して、許可された変更をコミットし、GitHubへ送ります。
3. **確認**：送信した版をリモートと照合します。未送信・失敗・確認不能はそのまま記録し、同期済みにしません。

保存先と範囲が合意済みなら、通常の保存ごとに同じ許可を聞き直しません。自動巡回は設定していないので、作業を担当するAIがこの手順を実施します。複数端末・複数担当で同時に作業するときは担当ブランチを分け、統合する担当と時点を決めます。

## 別のパソコンで再開する

1. 対応するAIアプリ、Gitと、このUIに必要なPython 3.9以降を準備します。
2. AIアプリへログインし、GitHubの本人用リポジトリへアクセスできることを確認します。
3. 新しい空き場所へクローンします。既に作業場所があるときは再クローンせず、未送信の変更を保って最新を取得します。
4. そのフォルダをAIの作業場所にして、次のように頼みます。

> 総えもんとして、この仕事場のAGENTS.md、目的、導入の記録と担当名簿、継続中の作業票を読んでください。使える道具を確認し、次の一手から再開できるよう案内してください。

総えもんは目的・担当・成果・次の仕事を読み取れるか確認し、不足する道具や素材だけを整えます。導入済みの動機の伴走役は作り直しません。保存済みの仕事場から続ける仕組みで、過去の会話全文やアプリの設定をそのまま複製するものではありません。GitHubへ送っていない変更は別端末へ移りません。

## 初回の再開確認

同じ端末の別フォルダへクローンし、目的・導入設定・担当・作業票・成果・次の行動がそろうか試せます。確認した版と方法・結果は作業票へ残し、[導入記録](../onboarding.md)からその原本へたどれるようにします。同じ端末での確認を、別端末・別OSで動作確認済みとは書きません。

## 準備済みの仕事場を遠隔で使う場合

現行の導入はPCを対象にしています。クラウドだけ・スマートフォンだけでの新規導入を、この手順の対応済み経路として案内しません。準備済みの仕事場を遠隔で使いたい場合は、同じ原本の読み書き・Python等の実行・永続保存・次回アクセスを別途確認します。端末ごとの設定や未送信の変更が自動で移ったとは扱いません。GitHub上で文書を直接編集する場合も、普段の作業場所で最新を取得して照合します。
