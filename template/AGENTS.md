# この仕事場で作業するAIへ

このファイルを含む雛形自体の制作・テストでは、親プロジェクトのAGENTS.mdに従う。以下は展開先での運用手順。

1. START.md、workspace/constitution.md、workspace/rules.md、workspace/purpose.mdを読み、目的と現在の担当を確認する。依頼済みの担当を聞き直さない。初回・再開の案内は総えもん（総務）がworkspace/onboarding.mdを確認し、workspace/agents/workflows/onboarding.mdに従う。最初の利用者専用担当として動機の伴走役を作り、再訪時は既存担当と記録を再利用する。
2. workspace/agents/registry.mdから役割原本を読む。引き継ぎでは作業票と成果物も読み直す。
3. 新しい複数工程の仕事はworkspace/operations/jobs/<作業ID>/TASK.mdへ記録する。原本を一つにし、開始・状態変化・終了や中断で更新する。初回の仕事場づくりも実際に着手した時点で記録し、onboarding.mdには設定とその原本への入口を置く。小さな単発質問のために票を増やさない。
4. 担当の追加・変更はworkspace/agents/workflows/add-desk.md、受け渡しはhandoff.mdに従う。総えもんは共通の係をrolesの役割文書、専門担当を担当定義込みのdesks文書として作り、名簿へ登録する。専門担当のプロフィール分離は共用したくなったときの選択肢。担当が机を増やす場合は名簿からたどれる案内を更新し、机だけの追加では担当IDを増やさない。同じ会話での兼務と別エージェントの起動を区別する。
5. 新しい担当は後から戻れる責任・原本・相談先を残すために作る。作成した担当と同じチャットでの兼務を一度紹介し、継続業務には理由を添えて専用チャットを勧める。ここで続ける選択肢も残し、別チャットの作成・送信は本人の依頼時に行う。口調や命名は必須質問にしない。同じ説明や修正が続くときはcollaboration-recovery.mdを読み、本人が試す余地を残し、必要ならAIが整理を引き受ける。
6. 作業開始時に共有板の開いている項目を読み、自分が対象なら本文の依頼と許可範囲に応じて返答する。ファイルの存在や画面閲覧を、全員の読了・合意とみなさない。
7. 既存の人間の編集と他担当の作業を保持する。変更前に対象を再読し、保存・復元はworkspace/recovery/README.mdを参照する。
8. 新しい担当・依頼・振り返りでは、共通の目的との関係を確認する。本人の意思とAIの解釈を分け、本人の明示的な変更を目的原本へ反映する。全案件で伴走役の返答を待つ必要はない。
9. GitHub保存を採用した仕事場ではworkspace/recovery/github.mdに従い、開始時に未送信変更とリモート更新を確認し、終了時に次の一手と許可された変更を保存・照合する。未接続・未送信を同期済みとしない。端末変更では導入済みの役割を再生成せず、作業票から続ける。

10. 別のどこでもデスクとの協働を頼まれたら、workspace/agents/workflows/mesh-collaboration.mdを読む。中庭を介して共有し、参加デスク全員の合意と各仕事場の実行権限を分ける。案内だけで外部共有や定期巡回を始めない。

役割は依頼時に担当する定義。自動起動、全会話の巡回、外部送信、公開、認証設定の包括許可ではない。架空の例を実際の仕事として進めない。実データの作業は、本人が依頼した対象と範囲で行う。
