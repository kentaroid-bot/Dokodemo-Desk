# どこでもデスク｜自分たちで育てるAI仕事場

**机の引き出しから、相棒がやってくる。**

最初の相棒は「総えもん（そうえもん）」。使い方の案内、エージェント作成、仕事場全体の取りまとめを担当します。「何ができるの？」「この仕事を手伝ってほしい」からご相談ください。

## まず、総えもんに話しかける

このフォルダを読み書きできるAIに、次のように頼みます。

> この仕事場のSTART.mdとAGENTS.mdを読み、総えもんとして案内してください。初めてなら、私が実現したいことを聞き、動機を受け持つ相棒を一緒に作ってください。導入の記録があれば、そこから続きを案内してください。

PCで使うAIが、実際にフォルダを読み書きし、Pythonを実行して画面を開けることを確かめます。初回試用はmacOSのCodexで確認しました。Antigravity・Hermesなどは、同じ能力を備えた環境での利用を想定し、実機での互換性確認はこれからです。同じ会話で役割を切り替えて始められます。プラグインは必須ではありません。

## 最初に、一緒に整えること

1. **やりたいことを聞く**。「何を実現したいか」「なぜか」「何を大切にしたいか」を、今ある困りごとから短く整理します。
2. **動機の伴走役を作る**。あなたの考えを理解し、仕事や次の提案を目的につなぐ相棒です。最初に作る利用者専用の担当にします。呼び名は自由に決められます。
3. **仕事場づくりを画面で確かめる**。この準備が最初の仕事です。総えもんとUI担当が、作った担当・導入の成果・続きの頼み方を記録と画面へつなぎます。
4. **保存方法と、次に頼むことを整理する**。手元だけ・ZIP・自分専用の非公開GitHubなどから選べ、後で決めることもできます。業務を始めるときは、必要な担当を紹介します。

話し方や名前は必要なときに調整します。決まっていない設定は仮のまま進められ、知っていることを何度も答える必要はありません。本体をGitHubから取得することと、自分の仕事をGitHubへ保存することは別です。

必要な係は、使いながら増やせます。役割を変えたり、休止したりもできます。動機の伴走役は「何のために、次に何をするか」、総えもんは「誰がどう受け持つか」、UI担当は「仕事を見えるようにすること」を受け持ちます。

## 担当ができたら、直接仕事を頼む

**担当を探すときは、[担当名簿](workspace/agents/registry.md)を開いてください。** 共通の係も専門デスクの担当も、ここに載っています。共通の係の役割はロール文書に、専門担当の役割はデスク文書の中に書いてあります。名簿のリンクから読めるので、保存フォルダを覚える必要はありません。

「作家を作って」と頼むと、総えもんが作家の役割と仕事の案内をまとめた執筆デスクを用意します。別の作品も同じ作家に頼めます。作品ごとに机を分けた方がよければ、その作家が整えます。最初から分け方を決め切る必要はありません。[共通の係と専門デスクの説明](workspace/agents/roles-and-desks.md)も読めます。

継続して相談する仕事には、後から続きを見つけやすい担当専用のチャットをおすすめします。総えもんが原本の場所と開始文を用意するので、説明をやり直さずに始められます。同じチャットで担当を兼務して続けることもできます。[仕事の引き継ぎ](workspace/agents/workflows/handoff.md)を参照してください。

## 他の仕事場と繋がりたいとき

[どこでもメッシュ](https://github.com/kentaroid-bot/dokodemo-mesh)を使うと、別のどこでもデスクとのあいだに、目的・約束・共同の仕事を置く「中庭」を開けます。各仕事場で考え、中庭へ返し、成果を持ち帰ります。内部の履歴を丸ごと共有する必要はありません。

総えもんへ「他のどこでもデスクと協働したい」と伝えてください。[メッシュ連携の案内](workspace/agents/workflows/mesh-collaboration.md)で、共有範囲・全員合意・巡回担当・終え方を整理します。接続や定期巡回は、この雛形だけでは始まりません。

## 仕事の地図を開く

総えもんに「画面も開いて」と頼めます。自分で開く場合は、このフォルダで次を実行し、ブラウザで http://127.0.0.1:8772 を開きます。Python 3.9以降が必要です。追加ライブラリや画面用のログインは使いません。

```text
python3 -B console/server.py
```

終了は起動した端末でControl+C。画面を開くか「記録を更新」を押すと、担当が残した原本を読み直します。画面が閉じていてもファイルから再開できます。

## 練習したい・別の端末で再開したい

- **まず練習**：[架空の制作室で一件を試す](examples/walkthrough.md)。例の動機・担当・金額は架空です。実際の導入には空の版が分かりやすく、練習版から始める場合も実案件と区別します。
- **自分の仕事場を再開**：[GitHubで保存・別端末で続ける](workspace/recovery/github.md)。最新のファイルを取得し、総えもんへ「この仕事場の続きから」と伝えます。
- **手元で保存**：[ZIPで保存・復元](workspace/recovery/README.md)。外部へ送らず、別の場所へ戻せます。

このv0.2の画面は読むためのものです。案内ボタンは手順を開き、AIを起動・通知しません。専用チャット、常駐、定期実行、使用量集計は未接続。名簿は担当の定義で、実行中の人数ではありません。
