# Dokodemo-Desk｜どこでもデスク

**机の引き出しから、相棒がやってくる。**

使い方を案内し、必要な仲間を作る「総えもん」から始める、ワークスペース型AI協働ハーネスです。目的・役割・仕事の記録と、全体を見渡す画面を、自分たちの仕事に合わせて育てます。

自分たちで育てるAI仕事場の**初期公開版**です。雛形v0.2を土台に、生成器・ローカルUI・導入と再開の手順をMITライセンスで提供します。MVPで得た改善をまとめ、2026-10-10から独立したGit履歴で開始します。

macOSのCodexを使う既存利用者の環境で、改訂した案内による導入と専用チャットでの再開を確認しています。新規利用者試験と、他のAI環境での確認はこれから行います。[確認範囲](VALIDATION.md)をご覧ください。

## たとえるなら、小さな船の航海です

「どこでもデスク」の役割分担は、海を行く小さな船によく似ています。

- **船 ＝ どこでもデスク**

  PCの中に置いて、どこへでも持ち運べるあなたの仕事場。
- **船長 ＝ 総えもん**

  船を切り盛りし、困ったときには、必要な仕事を担う仲間を一緒に考え、船に迎えてくれる頼れる番頭。
- **羅針盤 ＝ 動機の伴走役**

  あなたの言葉や仲間と進めた仕事から、「何を大切にして、どこへ向かいたいのか」を一緒に見つけていく役。見えてきた動機を記録し、次の進路を考える手がかりにします。
- **海図 ＝ 仕事の地図（UI）**

  誰が何を受け持ち、どこまで進んだかを一目で見渡す地図。
- **帆と風 ＝ AI**

  風をいっぱいに受けて、仕事をグングン前へ進める推進力。
- **旅人（乗客） ＝ あなた**

  「どこへ行きたいか」を決め、景色を楽しみ、航海そのものを進める主役。
  （ときどきマストの上で風を感じているカモメかもしれません）

仲間は、あなたの仕事に合わせて役割や頼み方を決めながら増やしていきます。

### 仕事をしながら、動機が見えてくる

最初から行き先をはっきり言葉にできなくても大丈夫です。例えば、ある旅館の仕事場なら、こんな歩みがあるかもしれません。以下は架空の例です。

1. **最初の相談**：「旅館の予約がめんどくさい」から、予約デスクとの仕事が始まった。
2. **1週間後**：予約対応を整理するうちに、同じ問い合わせの電話が多いと気づき、FAQを作った。
3. **1か月後**：スタッフの高齢化と対応の負担で、心の余裕が少なくなっていたことが見えてきた。本人の「宿の温かい空気を守りたい」という言葉から、効率化の先で大切にしたいことがつながった。

予約デスクや業務改善係は、予約対応やFAQづくりを進めます。動機の伴走役は、各係との仕事を通して見えてきた願いや判断軸をつなぎ、次の仕事に生かします。

気づいたときに「これ、動機の伴走役に記録して」と、いま話しているAIへ伝えるだけで構いません。AIから「これ、大切にしていることかもしれませんね」と返すこともあります。普通に一緒に仕事をする中で、その往復から見えてきたものを残していきます。最初に動機を完成させたり、毎回問い直したりする必要はありません。

その航海日誌にあたるのが、仕事場の`workspace/purpose.md`です。「いま分かっている目的」と「そこへ至った歩み」を残します。本人の言葉とAIの解釈を分け、過去の気づきも辿れるように育てます。記録は依頼や会話中の気づきをきっかけに、AIが参照できる会話・作業記録から行います。全チャットの自動巡回や定期起動は組み込んでいません。

## 対象と入口

**PCでAIと作業する人が、GitHubから本体を取得して始める**構成です。Gitの操作に習熟している必要はなく、取得先をAIへ渡し、準備を頼めます。

必要なのは、仕事場のフォルダを読み書きするAI、Python 3.9以降の実行、ローカルUIを表示するブラウザ、次回も原本を読める保存先です。初回試用を確認したのはmacOSのCodexです。Antigravity・Hermesなども、この能力を備えた環境での利用を想定します。アプリ名だけで互換性を保証せず、環境ごとに検証します。

クラウドだけ・スマートフォンのチャットだけで完結する新規導入は、現行の対象に含めていません。準備済みの仕事場を遠隔で使う方法は今後の検証対象です。「どこでも」は、利用者が所有する目的・役割・記録を持ち運び、対応する環境で続けられることを目指しています。

プラグインは、見つけてもらいやすさや導入の分かりやすさを補う将来案です。本体の利用条件ではなく、全チャット利用者への提供や公式の品質保証を意味するものでもありません。

## このチャットで使ってみたい方へ

PCで使うAIへ、リポジトリのURLとともに次のように依頼してください。

> https://github.com/kentaroid-bot/Dokodemo-Desk から本体を取得してREADMEを読み、総えもんとして「どこでもデスク」を案内してください。別の新しいフォルダに私の仕事場を作り、最初の画面を見るところまで手伝ってください。

AIは[総えもんの役割](template/workspace/agents/roles/general-affairs.md)と[初回案内](template/workspace/agents/workflows/onboarding.md)を案内用として読みます。このtemplateに含む目的や仕事は架空の練習例です。本人の動機として扱わず、下の空の版を生成してから、その仕事場のSTART.md・AGENTS.md・導入記録へ進んでください。

保存場所を決め、いま分かっている困りごとや願いから動機の伴走役を作ります。動機は仕事をしながら育てていけます。最初からいる総えもん・UI担当は重複して作りません。役割の定義、同じ会話での兼務、別チャットの起動は区別して説明します。

仕事場づくり自体を最初の仕事として記録し、画面で担当・成果・続きの頼み方を案内します。話し方や名前は必要に応じて調整でき、設定の質問を全部終えるまで待つ必要はありません。継続する業務には、続きを見つけやすい専用チャットを提案し、同じチャットで続けることもできます。

総えもんは、仕事場全体を支える係をロール文書に、作家などの専門担当を担当定義込みのデスクにまとめます。「作家を作って」と頼めば、役割と仕事の案内を含む執筆デスクから始められます。詳しくは[共通の係と専門デスク](template/workspace/agents/roles-and-desks.md)をご覧ください。

## 取得する

Gitを使う場合は次を実行します。公開リポジトリの取得にGitHubへのログインは不要です。

```text
git clone https://github.com/kentaroid-bot/Dokodemo-Desk.git
cd Dokodemo-Desk
```

Gitを使わない場合は、GitHubの「Code → Download ZIP」から取得して展開できます。

固定した版で試す場合は、指定されたコミットへ切り替えてから始めます。取得したこのフォルダは雛形の配布元です。利用者の仕事場は別の場所に作り、本人のGitHubへ保存するかは後から決められます。

## 新しい仕事場を作る

Python 3.9以降を使います。追加ライブラリや画面用のログインは不要です。配布元のフォルダで実行します。

```text
python3 -B create_workspace.py ../my-workspace --name "私たちの仕事場" --blank
```

保存先が既にあるときは生成せず停止します。自分の仕事場の名前と保存先へ置き換えてください。生成後は、その仕事場のSTART.mdをAIに読んでもらいます。

空の版には総えもん・UI担当の2役だけがあり、本人との対話で動機の伴走役を最初に加えます。架空の制作室で練習したい場合は、別の場所へ練習版を生成します。

```text
python3 -B create_workspace.py ../practice-workspace --name "練習の制作室"
```

練習版は架空の伴走役・見積担当を含む4役と、仕事・日報・回覧の例があります。実業務へ架空の記録を引き継がないよう、空の版と分けて使います。

## 仕事の地図を開く

**生成した仕事場**のフォルダで実行し、ブラウザで http://127.0.0.1:8772 を開きます。

```text
python3 -B console/server.py
```

同じポートを別の仕事場が使っている場合は、`--port 8773`など空いている番号を指定します。終了は起動した端末でControl+Cです。

画面には担当・仕事・日報・共有板・案内が表示されます。画面を開くか「記録を更新」で原本を読み直します。名簿は実行中のAIの人数ではなく役割の一覧です。通知、常駐、別チャットの自動起動、モデル使用量の取得は接続していません。

## 開発する方へ

```text
python3 -B -m unittest discover -s tests -v
node --check template/console/app.js
```

Node.jsはJavaScriptの開発時確認に使います。仕事場を動かすための必須依存ではありません。

今後の雛形の開発原本はこの公開リポジトリです。利用者が生成した目的・役割・仕事をtemplateへ戻さず、雛形の更新でも本人の編集を上書きしません。

不具合や改善案は[Issues](https://github.com/kentaroid-bot/Dokodemo-Desk/issues)へ。再現手順と環境を添え、本人の業務記録や認証情報は掲載せず、架空の例で説明してください。
